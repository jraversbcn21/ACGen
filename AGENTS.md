# ACGen — Agent guide

## Commands (run from `acgen/`)

| Command | Action |
|---|---|
| `npm run dev` | Start Vite dev server (port 5173) |
| `npm run build` | Type-check (`tsc -b`) + Vite build |
| `npm run lint` | ESLint |
| `npm run preview` | Vite preview |
| `npm test` | Run unit tests (Vitest) |
| `npm run test:watch` | Run tests in watch mode |
| `npm run test:ui` | Run tests with Vitest UI |

## Architecture

- **React 18 SPA**, Vite 5, TypeScript. 100% static deploy. All core logic in-browser.
- **Hash-based routing** (`#/landing`, `#/acceptance`, `#/testcase`, etc.) via `getViewFromHash()` + `hashchange` listener. `navigate(view, { prefill? })` callback. Browser back/forward and F5 work.
- **ViewType**: `'landing' | 'acceptance' | 'testcase' | 'bugreport' | 'testdata' | 'sprinttracker' | 'regressiontracker' | 'userstory' | 'refiner' | 'edgecase' | 'converter' | 'designvalidator' | 'doclibrary'`
- **App shell**: `<I18nProvider>` > `<div className="page">` > `<Header>` + `<div className="app-layout">` > `<Sidebar>` + `<main className="container">`. Sidebar hidden on landing.
- **Sidebar**: collapsible icon-nav grouped by category (Generar/Refinar/Convertir/Seguimiento) + active workspace name + prompt editor link. Active highlight via hash.
- **View router** wrapped in `<ErrorBoundary key={view}>`: class component with `getDerivedStateFromError`/`componentDidCatch`, renders recoverable fallback. Keyed by `view` so switching tools remounts it.
- **Settings persistence**: API keys stored per provider (`acgen_key_groq`, `acgen_key_openrouter`, `acgen_key_custom`). Model stored as `acgen_model`. Provider stored as `acgen_provider`. Theme as `acgen_theme`. Language as `acgen_lang`. Workspaces as `acgen_workspaces`. Project profile as `acgen_project_profile`. History, sprints, and sprint configs in their own keys. Regression tracker versioned regressions+archived (+ opaque legacy `board`) as `acgen_regressions`, ticket-table column widths as `acgen_regression_ticket_col_widths`, legacy-snapshot grid widths as `acgen_regression_col_widths`. The trackers' configurable schema lives in `acgen_schema` (`STORAGE_KEYS.SCHEMA`): `regression: { ticketFields, platforms }` (Fase 4) plus `sprint: { tabs: SprintTabSchema[] }` (Fase 5) — each sprint tab is a `SchemaEntry` (id/labelKey/label/hidden) that additionally carries its own `columns: SchemaEntry[]`, since the Sprint Tracker's grid is per-tab. With nothing stored the app falls back to `DEFAULT_SCHEMA`, which is an exact encoding of today's wired-in field list, platform tabs, and sprint tabs+columns — so a user who never opens either schema editor sees byte-identical behavior. Last backup timestamp as `acgen_last_backup` (`STORAGE_KEYS.LAST_BACKUP`).
- **`useLocalStorage` cross-instance/cross-tab sync**: dispatches custom `acgen-local-storage` window event + listens for native `storage` event. All writes wrapped in try/catch for `QuotaExceededError`.
- **LLM API**: provider-agnostic via `baseUrl` parameter. Supports Groq (default), OpenRouter, and Custom (any OpenAI-compatible endpoint). Called via `fetch` with SSE streaming. Temperature fixed at `0.2`.
- **Streaming**: `streamWithGroq()` async generator yields tokens progressively. `useStreamingResponse()` hook manages state. Supports optional `anonymizeMap` for confidential mode and `baseUrl` for multi-provider.
- **Design tokens**: `:root` invariants + `[data-theme="light"]` / `[data-theme="dark"]` in `App.css`. Key tokens: `--accent` (purple), `--bg`, `--surface`, `--border`, `--text`, `--text-2`, `--text-3`, `--radius` (16px), `--radius-sm` (11px), `--shadow-sm/md/lg`. Fonts: Manrope, Newsreader italic, JetBrains Mono.
- **Theme**: light/dark via `[data-theme]` on `<html>`. Applied synchronously from localStorage before paint. Toggle in Header.
- **i18n**: `I18nContext` + `useT()` hook. `es.json` and `en.json` (442 keys, exact parity, guarded by `src/i18n/keyParity.test.ts`). Language toggle in Header (ES|EN). Detects browser language on first visit. Missing keys fall back to Spanish. Parameter interpolation supported.
- **SVG Icons**: `src/components/Icons.tsx` exports `Icon` object with named components. All 24x24, stroke-based, `currentColor`, `strokeWidth` 1.6.
- **Shared CSS**: form fields, buttons, tables, badges, modal overlay, action bar, model badge, searchable select, sprint spreadsheet, error boundary fallback, toast, update banner in `App.css`. `.tool-head`/`.tool-head-aside` is the current header pattern for a tool screen (richer than the older `.tool-page-title`). The pre-redesign `.tool-split`/`.actions-col`/`.result-box`/`.tool-fill` family is **gone**: `EdgeCaseTool` was its last consumer and the Casos Limite redesign removed both the markup and the rules (including their `@media` overrides).
- **Per-screen CSS families**, one per redesigned tool, each self-contained near the end of `App.css`: `.us-*` (Historia de Usuario), `.dv-*` (Validador), `.cv-*` (Conversor), `.sp-*` (Sprint list), `.rf-*` (Refinador), `.ec-*` (Casos Limite), `.ld-*` (portada/console), `.dl-*` (Doc Library), plus the older `.br-*` (Bug Report), `.td-*` (Datos de Prueba), `.tc-*` (Casos de Prueba) and `.criteria-*`. **The `@media (max-width: 1200px)` block must stay last in the file** — the base `.sidebar` / `.app-layout .container` rules live around line 1000 and win by cascade otherwise. New families go *before* it.
- **PWA**: `vite-plugin-pwa` with `prompt` register type, manifest, icons (192+512), workbox static precache of JS/CSS/HTML/fonts. Update flow is manual (`virtual:pwa-register` wired in `useAppUpdate.ts` with `immediate: true`, not the plugin's auto-injected script): the new service worker installs but waits (`skipWaiting: false`, gated behind the `SKIP_WAITING` message); `<UpdateBanner>` appears when `onNeedRefresh` fires and only reloads when the user clicks "Actualizar". **`clientsClaim: true` is load-bearing**: in prompt mode the plugin doesn't set it, and without it the newly-activated SW never takes control of already-open pages, `controllerchange` never fires and the button silently does nothing (found live by Jorge). `reload()` is belt-and-suspenders: `updateServiceWorker(true)` + a `controllerchange` listener that reloads via `reloadPage()`, plus a 2s fallback reload for uncontrolled pages (e.g. after a hard refresh) — the button always behaves as a guaranteed reload. A background check (`registration.update()`) runs every hour so a tab left open still notices new deploys.

## Cross-cutting features

### Confidential mode (Modo confidencial)

- `src/services/anonymizer.ts`:
  - `anonymize(text)` / `deanonymize(text, map)` — 7 regex patterns in order: EMAIL, URL, IP, TICKET, PHONE, DOMAIN, NAME. `deanonymize` restores in REVERSE insertion order (2026-08-16): a later pattern (URL) can wrap an earlier pattern's placeholder (EMAIL) inside its original value, so the wrapper must be restored first
  - `applyPlaceholderEdits(text, map, edits)` — rewrites text and restore map together when the user renames a placeholder in the review modal
  - `splitPendingPlaceholder(text, mapKeys?)` — splits streamed text into an emit-safe part and a tail that may still grow into a placeholder (used by `streamWithGroq` so a placeholder split across two SSE chunks still resolves). With `mapKeys` (the restore map's real keys, passed by `streamWithGroq` since 2026-08-16) it holds back any tail that is a proper prefix of a key — free-text renames from the review modal have no `[PREFIX_n]` shape and the default regex could not protect them; the regex remains as the no-map fallback
- `<ConfidentialToggle view text onReview>` — per-tool checkbox, persisted as `acgen_confidential_{view}` in localStorage. Takes the exact text the tool would send and counts substitutions itself (memoized, only while enabled); the badge and "N sustituciones — Revisar" link render only once that count is above zero.
- `<AnonymizerReview map onConfirm onCancel>` — modal showing substitution table (Original | placeholder) before the API call. Editable per row; `onConfirm` receives only the renamed placeholders (`edits`), not the full map — callers run them through `applyPlaceholderEdits` before sending.
- `streamWithGroq()` accepts `anonymizeMap` parameter — deanonymizes streamed text (buffered via `splitPendingPlaceholder`, not per raw token) in real time
- Opt-in (off by default). Review modal shown before every API call when enabled and something matched
- `useGenerator` (shared by the 9 tools) holds a single `review: { text, map } | null` state: `openReview()` builds it by running `buildInput()` through `anonymize()`; `confirmReview(edits)` applies the renames via `applyPlaceholderEdits` and calls `run(text, map)` — `text` is the *anonymized* string that actually gets sent to the API, never the raw input

### Workspaces

- `src/types/workspace.ts` — `Workspace { id, name, createdAt, artifacts[] }`, `Artifact { id, tool, input, output, timestamp }`
- `useWorkspace()` hook — CRUD, `exportWorkspace(id)` returns the JSON string (does not download it), `importWorkspace(json)` validates and throws on malformed input
- `src/utils/download.ts` — `downloadBlob(filename, content, mime)` (Blob → anchor click → revoke; `downloadJson` wraps it and Conversor/Datos de Prueba call it directly since PR #58) and `toFilename(name, ext)` (slugifies; strips path separators so a workspace named `../../etc/passwd` can't escape the downloads folder). `App.tsx`'s `exportWorkspaceToFile` wires the two together — `useWorkspace().exportWorkspace` alone does not trigger a download.
- `<WorkspacePicker>` in Header — dropdown with create/rename/select/export/import, fully i18n'd. Delete is a 2-step inline confirm (`¿Eliminar "<name>"?` / confirm / cancel) naming the workspace, not a single click and not `window.confirm`.
- Auto-save: each successful generation saves artifact to active workspace via `onSaveArtifact` → `useWorkspace.saveArtifact(artifact, fallbackName)`, which owns target resolution: uses `activeId` when it points at an existing workspace, otherwise (null OR stale id from corrupted/cleared storage, OR a workspace deleted while the stream was running) auto-creates a "Sin nombre" workspace and saves there — no silent data loss. Since 2026-08-16 the existence check reads `localStorage` at call time instead of the closure's `workspaces`: tools capture this callback at generation start and invoke it on completion seconds later, so the closure list is frozen while `useLocalStorage` has already written every intervening update synchronously — validating against the stored value is what closes the delete-mid-stream race. The closure's `activeId` still picks the DESTINATION (saving where the generation started is intended); only existence is checked against the present.
- Sidebar shows active workspace name

### Backup & persistence

- `src/services/backup.ts` — pure logic core, no React. `collectBackupData({includeApiKeys?})` snapshots every `acgen_*` localStorage entry verbatim (no `JSON.parse` — values are heterogeneous JSON/raw-string/bare-literal), always excludes `acgen_last_backup`, excludes the API-key family (`acgen_key_*` + legacy `acgen_api_key`, matched via `isSensitiveKey`) unless opted in. `createBackup(opts)` wraps that into a pretty-printed `{schemaVersion: 1, exportedAt, data}` JSON string (`BACKUP_SCHEMA_VERSION`). `parseImportFile(json)` classifies an imported file as `backup` / `legacyWorkspace` (pre-dates this feature — single-workspace export, recognized by `id`+`name`+`artifacts[]` shape) / `futureVersion` / `invalid` (`json` or `structure` reason). `restoreBackup(backup)` is a total replace of the current `acgen_*` state with the backup's `data`: always preserves `acgen_last_backup`, preserves local API keys when the backup itself carries none, rejects tampered entries whose key doesn't start with `acgen_`, never touches non-`acgen_` keys, and on `QuotaExceededError` rolls back to the exact pre-restore snapshot and returns `{ok: false, error: 'quota'}`. Plus reminder logic: `hasSignificantData()` (true if any workspace has an artifact, any sprint exists, the regression board has a filled cell or an archived run, or criteria/bug history has an entry — corrupt JSON in any one source counts as "no data" for that source, not a throw), `isBackupDue(lastBackupAt, now?)` (true when there's significant data and either no backup was ever made or the last one is older than `BACKUP_REMINDER_DAYS` = 7), `acgen_last_backup` is read and written directly through `useLocalStorage` in `src/hooks/useBackupReminder.ts` (the old `getLastBackupAt()`/`markBackupDone()` wrappers had no consumer outside their own test and were deleted in PR #58).
- `src/hooks/useBackupReminder.ts` — thin `useLocalStorage(STORAGE_KEYS.LAST_BACKUP, null)` wrapper exposing `{due, lastBackupAt, markDone}`; `due` is `isBackupDue(lastBackupAt)` recomputed on every render.
- `src/components/BackupMenu.tsx` — dropdown mounted in `Header` next to `WorkspacePicker` (💾 icon, reminder badge when `due`). Export: checkbox "incluir API keys" (plain-text warning shown when checked) → `createBackup` → `downloadJson`/`toFilename` → `markDone()`. Import: reads the file, `parseImportFile` routes it — `backup` goes through an inline 2-step confirm (`backup.confirmReplace` / yes / cancel) before `restoreBackup` + `onRestored` (defaults to `location.reload()`); `legacyWorkspace` calls `onImportLegacyWorkspace` (wired to `useWorkspace.importWorkspace` in `App.tsx`) directly, no confirm — wrapped in try/catch because `parseImportFile`'s shallow shape check accepts files `importWorkspace` still rejects (e.g. empty-string `id`): a throw shows `backup.importError` instead of failing silently; `futureVersion`/`invalid` show an `alert()`. A quota failure on confirm shows `backup.quotaError` and leaves the pending state so the user can retry or cancel.
- `src/services/autoBackup.ts` + `src/types/fileSystemAccess.d.ts` — File System Access API service (Chromium-only: `isFileSystemAccessSupported()` checks `'showSaveFilePicker' in window`). `chooseBackupFile()` opens the native save picker (`suggestedName: 'acgen-auto-backup.json'`), resolves `null` on user cancel (`AbortError`), otherwise propagates other errors. The chosen `FileSystemFileHandle` is persisted in IndexedDB (`saveHandle`/`loadHandle`/`clearHandle`, DB `acgen-backup` → store `handles`, fixed key `autoBackupFile`) since it's the only storage that survives a reload with a live handle. `ensurePermission(handle)` resolves readwrite permission, prompting via `requestPermission` if needed, falling back gracefully when `queryPermission`/`requestPermission` aren't implemented. `writeSnapshot(handle, contents)` never rejects — permission denial, a rejecting permission check (e.g. `SecurityError` without a user gesture, or a revoked handle), or any write I/O failure all resolve to `false` so callers can show a soft warning instead of crashing.
- `src/hooks/useAutoBackup.ts` — state machine `'unsupported' | 'off' | 'active' | 'permissionNeeded' | 'error'`. On mount, resolves a persisted handle without prompting for permission (that needs a user gesture). `enable()`/`disable()`/`reconnect()` are the only user-gesture entry points. While `active`, listens for `acgen-local-storage` (same-tab, fired by `useLocalStorage`) and the native `storage` (cross-tab) events and writes a snapshot debounced 5s (`DEBOUNCE_MS`) after the last change. Events whose changed key is `acgen_last_backup` are ignored (the CustomEvent's `detail.key` / `StorageEvent.key` identifies it; events with no key info fail open and schedule): without this filter, every successful snapshot's own `markDone()` write would re-trigger the listener and produce an infinite snapshot→`markDone`→snapshot loop rewriting the disk file every 5s. Skipping it loses nothing — `collectBackupData` excludes that key, so its change alone can never alter snapshot content. Every snapshot calls `createBackup({includeApiKeys: false})` — auto-backups never include API keys — and a successful write calls the `onSnapshot` callback (wired to `useBackupReminder().markDone` in `BackupMenu`) so auto-backups also satisfy the 7-day reminder. Guards a stale in-flight write: if the handle changed (or was cleared by `disable()`) while a debounced/`enable()` write was in flight, the result is dropped instead of resurrecting `'active'`. The auto-backup UI section in `BackupMenu` renders only when `isFileSystemAccessSupported()` is true — hidden entirely in Firefox/Safari.
- `src/services/persistence.ts` — `writeStorage(key, value)`, the single localStorage write path shared by `useLocalStorage`/`useSprints`/`useRegressions`/`useHistory` (fires `acgen-local-storage` for same-tab sync and `acgen-storage-error` on quota, which `StorageQuotaAlert` turns into a once-per-session `alert`); `requestPersistentStorage()` calls `navigator.storage.persist()` once; resolves `false` (never throws) when the API is absent or `persist()` rejects. Invoked fire-and-forget (`void requestPersistentStorage()`) once at `App.tsx` mount to reduce the odds the OS evicts localStorage under storage pressure.
- **Known limitations (accepted, not bugs)**: `useSprints`/`useRegressions`/`useHistory` write `localStorage` directly without dispatching `acgen-local-storage`, so a change made only through those hooks doesn't trigger an immediate auto-backup snapshot — it's captured by the next change that does dispatch the event, or once the page reconnects. Auto-backup to a local file is Chromium-only (no File System Access API in Firefox/Safari). Changes made in the ~5s debounce window right before closing the tab can be missed by auto-backup. "Clear site data" wipes the IndexedDB handle (the auto-backup connection), though the file already written to disk survives — the user just has to re-pick it via `reconnect()`.

### Sprint Tracker

- Fully offline — no LLM dependencies
- **Schema-driven tabs and columns, like the Regression Tracker (Fase 5)**: tabs and each tab's columns come from `useSchema()` (`schema.sprint.tabs: SprintTabSchema[]`, `src/types/schema.ts`) instead of being hardcoded. A `SprintTabSchema` is a `SchemaEntry` (id/labelKey/label/hidden — same shape and same "id never changes, label wins over labelKey, hidden never deletes" rules as Regression's fields/platforms) that additionally carries its own `columns: SchemaEntry[]`. With nothing saved to `acgen_schema` the tabs and columns are exactly today's five: Resueltos, Creados, ReOpen, Prioridad Alta, JSD, each with its historical column set (JSD's grid is 6 columns wide but only 3 are named — see `colCount` below).
- **`TrackerGrid.tsx` (the spreadsheet shared with the Regression Tracker) takes a resolved `tabColumns: Record<T, {label, dataIndex}[]>` prop — it never sees the schema.** `SprintDashboard.tsx` is the resolver: for the active tab it maps every schema column to its own index in that tab's `columns` array (`dataIndex`, computed BEFORE filtering hidden entries — filtering first would silently shift every later column's data index onto the wrong cell) and only then drops the hidden ones. `TrackerGrid` just paints whatever `{label, dataIndex}` list it's handed, in that order, with zero schema awareness. A second prop, `tabColCount: Record<T, number>`, carries **how many columns the caller declares for that tab, hidden ones included** (`SprintDashboard` passes `tab.columns.length`; `RegressionTracker` passes `LEGACY_HEADERS.length`) — without it `TrackerGrid` cannot tell "extra unlabelled data column, must render" from "column the user just hid, must not", and hiding the last column of a tab silently did nothing. `colCount = Math.max(columns.length, grid[0]?.length ?? 0, 1)`: deriving column count from headers alone would hide any stored data column past the last known header — JSD ships 3 header columns over a 6-wide grid, so the `grid[0]?.length` floor keeps D/E/F rendering (unlabeled) instead of making their data vanish from the screen. The trailing unlabelled columns are appended starting at `Math.max(maxNamed + 1, declaredCount)`, and that `declaredCount` floor is exactly what stops a hidden last column from reappearing as an unlabelled one. Everything else indexes by `dataIndex` (data position), never by visual (on-screen) position: stored column widths (keyed `${tab}-${dataIndex}`), `cellRefs`, the `data-col` attribute, `onUpdateGridCell`'s `col` argument, and the A/B/C... column letters (`colToLetter(dataIndex)`) — hide column B and the remaining letters read A, C, D... not A, B, C. The one exception is ←/→ arrow-key navigation between cells, which walks the visual order (what's next to what on screen), because that's what a user pressing an arrow key expects.
- **Search divergence from the Regression Tracker is deliberate, not a bug**: `TrackerGrid`'s debounced (250ms) search matches every cell in the row array, hidden data columns included — a value sitting in a column the user hid still surfaces its row. This is the OPPOSITE of the Regression Tracker, where Fase 4 scoped search to only the schema's *visible* ticket fields. Jorge's call on 2026-08-15: hiding a column is a view preference, not a deletion, so the Sprint Tracker's search treats hidden data as still-searchable; the Regression Tracker's narrower Fase 4 behavior was left as-is rather than "fixed" to match. Pinned by `TrackerGrid.test.tsx`'s "tabColumns por indice de datos" describe block precisely so this divergence doesn't get flattened by someone reading the two trackers side by side. Also see "Known issues".
- **Cannot delete or reorder tabs/columns — deliberate, see "Known issues"**: the grid is positional (a column's screen position and its `dataIndex` are the same number), so either operation would require migrating to keyed rows plus migrating every stored width from index-keyed to id-keyed. Hiding already covers the practical case.
- **`useSchema()` normalizes each sprint tab to always have a `columns` array**: a hand-written or half-restored `acgen_schema` can carry `{"tabs":[{"id":"resolved","label":"R"}]}` — `Array.isArray(sprint.tabs)` is true so the per-list fallback doesn't fire, and `tab.columns.filter(...)` then threw inside `SprintSchemaEditor`, which `App.tsx`'s per-view `ErrorBoundary` turned into a dead Sprint Tracker view with the "Restaurar por defecto" escape hatch trapped inside the crashed component. Normalizing once in `useSchema`'s `useMemo` (`Array.isArray(t?.columns) ? t : { ...t, columns: [] }`, which also covers `columns` being some non-array) fixes every consumer at once instead of scattering `?? []` across the four call sites. Consequence worth knowing: the normalization is **write-through**. Callers write by spreading the object the hook returns (`setSchema({ ...schema, sprint: ... })`) and `setSchema` merges shallowly per section, so editing *any* tab re-persists *every* normalized tab. For a tab that was simply missing its `columns` key that is additive and harmless. **It is not harmless if `columns` ever holds a non-array with real content**: the normalization replaces it with `[]` in memory and the next schema write of any kind persists that, losing whatever was there. No path reaches this today (it needs a hand-edited `acgen_schema`), but **before Fase 6+ reuses the `columns` key with different semantics, either narrow the normalization or make it in-memory only** — this is the one case where "additive, never destructive" does not hold.
- **`useSprints()` backfills each sprint's `tabGrid` against the schema's current tabs in the hook's RETURN value (a `useMemo`), not just once at mount**: the schema can gain a tab after the hook already mounted (live schema editor, another tab via the `storage` event), and the initial `useState` backfill only ever runs once. Deriving the "every sprint has a grid for every schema tab" invariant on every render — without touching `sprints` state or the persistence effect — means a freshly added tab is immediately writable instead of showing 0 rows until a reload. `updateGridCell`/`moveRow` read the raw state through the same fallback (`gridFor`), so the very first edit on a newly materialized tab is never a silent no-op either.
- Editable spreadsheet grid (20 rows per tab by default), resizable columns, drag-and-drop rows, Ctrl+click ticket links, keyboard navigation, SnapLink paste support
- **Columns/tabs editor**: a "Pestañas y columnas" text button (`schema.sprintOpen`) above the grid opens `SprintSchemaEditor.tsx`. Unlike `RegressionSchemaEditor`, it lists ALL tabs at once — not just the active one, since `activeTab` is `TrackerGrid`'s own internal state and pulling it out for the editor to read would be far more invasive than just listing all five — each with its columns nested underneath, via the shared `SchemaEntryRow.tsx`: rename (local draft commits on blur, same as Regression's editor), add, hide, no Save button, writes go straight to `acgen_schema`. A new tab starts with a CLONE of the first default tab's columns (never the live `DEFAULT_SCHEMA` reference) so it's never born with nothing to show. A guard blocks hiding the last visible tab, or the last visible column within a tab. "Restaurar por defecto" resets only the `sprint` section — the merge-on-write `useSchema()` fix from Fase 4's final review already protects the `regression` section from this button, and the reverse now holds too.
- **Sprint list (rewritten in PR #43) — the gesture changed and it is a behavioural contract**: clicking a sprint in the side list only **selects** it into the hero (`setSelectedId`); the board opens **only** via the hero's "Abrir tablero" (`sprint.openBoard` → `onSelectSprint`). Anything that navigates by clicking the sprint name — tests, browser-checks — has to click the item and then the button; the five `scripts/browser-checks/*.mjs` share an `openBoard(name)` helper for exactly this.
- Layout: `.sp-root` = `.tool-head` (title + `{active}/{archived}` counters + "Nuevo Sprint") over `.sp-grid` (main + `.sp-side`). `.sp-main` holds the hero of the **selected** sprint (badge `sprint.current` + `sprint.day`, inline rename via `.sp-hero-name-input`, dates, actions Abrir tablero / Renombrar / Archivar / Eliminar, plus `.sp-metrics`), then three panels: rows-per-tab bars, **Actividad reciente** and **Por squad**. `.sp-side` is the searchable list, grouped Activo/Archivados, with `.sp-dot-current|active|archived` and mini Desarchivar/Eliminar actions.
- Selection is **derived, not stored**: `sprints.find(selectedId) ?? active[0] ?? null`, so a deleted or archived sprint can't leave the hero pointing at nothing. With no active sprints and nothing selected the main column shows `sprint.noCurrent`.
- `.sp-panel` is `flex: none`, **not `flex: 1`**: the bar list has one row per tab (5 by default), so stretching it to the column height just drew a half-empty frame (caught by Jorge on review). The same reasoning applies to any panel added here.
- `activityRows()` flattens the rows with content across visible tabs, resolving each column **by `col.id` over `tab.columns` without filtering hidden ones** — the index varies per tab (ReOpen has Motivo where Resueltos has Prioridad/Autor), so positional access silently reads the wrong column. Sorted by `parseCellDate` descending; rows whose date doesn't parse go last rather than sorting as `NaN`.
- Sprint cards used to carry 🟢/🔴 emoji and an "Editar" button; both are gone (dots are CSS now, rename lives in the hero and is labelled `sprint.rename`). `sprint.archivedBadge` is still the singular badge, `sprint.archived` still the plural section header.
- Storage: sprints (each with a per-tab `tabGrid`) in `acgen_sprints`; the schema (tabs + their columns) shares `acgen_schema` with the Regression Tracker's schema under its own `sprint` key, so a write to one section never touches the other

### Regression Tracker

- Fully offline — no LLM dependencies
- **Versioned regressions, not a free grid**: platform tabs and ticket-table columns both come from `useSchema()` (`src/hooks/useSchema.ts`, `src/types/schema.ts`) rather than being hardcoded. With nothing saved to `acgen_schema` the tabs and columns are exactly today's: APPS (internal id `ios`, label "APPS") and WEB (internal id `webDesktop`, label "WEB") — internal ids kept historical so existing localStorage data survives renames — and the ticket fields Ticket/Fecha/Prioridad/Creador/Squad/Status. A `SchemaEntry`'s `id` is a storage key that **never changes**; renaming writes a literal `label` that wins over the default `labelKey` translation (a renamed column reads the same in ES and EN); hiding an entry only sets `hidden` and never deletes its data — a hidden ticket field stays on every stored ticket, a hidden platform's regressions stay under `regressions[id]`, and both come back exactly as they were the moment the entry is shown again. Fields and platforms removed from the schema this way (or from an older, smaller schema) are kept but orphaned — same "huérfano pero intacto" convention the legacy `board` already uses. Each tab is a list of `Regression { version, url, fecha, tickets[] }` cards, newest first; "+ Nueva regresión" creates one with 3 empty ticket rows (version required, url/fecha optional)
- **Redesigned layout (PR #46, `.rg-*`)**: `.tool-head` (title, per-tab subtitle with regression/ticket counts, Columnas + SnapLink on the right) over `.rg-grid` — a left **rail** (platform tabs with `role="tab"`, search, "+ Nueva regresión", one `.rg-item` per version with filled-ticket count and date) and a right **detail panel** rendering the selected version's `RegressionCard` with `variant="panel"` (header with version/link/date/ticket badge/status summary + Editar/Archivar/Eliminar, sticky-header table filling the height, "+ Añadir ticket" and the Ctrl+click hint in the footer). Selection is **per platform** (`selectedIds: Record<PlatformId, string>`): switching APPS→WEB→APPS restores the version you were looking at; a selection that no longer passes the filter falls back to the first visible. **Creating a version clears the platform's selection so the detail lands on the new version** (addRegression prepends). The status summary counts the raw user-typed `status` values (top 3, no fixed vocabulary) and hides with no status column or no values.
- `RegressionCard.tsx`: two variants sharing every building block (`editFields`/`urlLink`/`rowActions`/`ticketTable`). **`variant="panel"`** (the tracker detail) never collapses and gets sticky `<th>`; **`variant="card"`** (default) keeps the collapsible header (version, an accent link opening in a new tab, formatted date, filled-ticket badge, Editar/Archivar/Eliminar) that expands into a ticket table whose columns are the schema's visible ticket fields, each resizable by dragging the header's right edge (widths keyed by field id in `acgen_regression_ticket_col_widths`, shared across cards and both tabs; ephemeral in readOnly snapshots). "+ Añadir ticket" appends rows; the per-row × asks `confirm` only when the row has any content (an empty row deletes silently). The "Nombre - URL" link-cell rendering (name overlay at rest, full value on focus, Ctrl+click or the ↗ icon opens it, via the shared `src/utils/trackerLinks.ts#parseUrlCell`) is applied to the **first visible column**, not to a hardcoded `ticket` field id — under the default schema that's the same cell as before, but the behavior survives renaming or hiding earlier columns. **Columns editor**: a "Columnas" text button in the tab bar (plain text, not a ⚙ icon — `TrackerGrid` already uses ⚙ for the tracker base URL) opens `RegressionSchemaEditor.tsx`, which lists both the ticket fields and the platforms via `SchemaEntryRow.tsx` — rename, add and hide, each writing straight to `acgen_schema` with no Save button (the rename input alone keeps a local draft that commits on blur, so clearing it to retype can't wipe the label). Adding works identically for ticket fields and platforms (same UUID id, appended to the end of its list, empty name is a no-op) — a team testing iOS and Android natively is no longer capped at the two default tabs. A guard blocks hiding the last visible entry of either list. "Restaurar por defecto" resets only the `regression` section of the schema; `useSchema()`'s write path merges every write against what's actually stored (not just what this phase's `schema` return value knows about), so any section a later phase adds (e.g. Fase 5's `sprint`) survives untouched through resets, renames or any other schema write, not only the reset button
- **Per-regression archiving**: "Archivar" on a card asks `confirm`, then moves that single regression (not the whole tab) into `archived` as `{ id, archivedAt, platform, regression }`, labeled `"<platform label> · <version>"` in the history list — the label is resolved from the schema's current platform entry, so a renamed platform relabels its old archived entries too, and one whose entry was hidden or removed still resolves (falling back to the raw platform id, never a blank label); opening it renders the same `RegressionCard` read-only and already expanded (no Editar/Archivar/Eliminar, ticket inputs readOnly)
- **Mixed history**: `archived` is a discriminated union (`isLegacyArchived()` checks for a `board` key) — old-style archived snapshots from the pre-2026-08-10 free 20×6 grid still open with the legacy read-only `TrackerGrid` (headers Regresión/Versión/Fecha/Notas/Status). The pre-migration live board itself (top-level `board` key in `acgen_regressions`) is hydrated and re-persisted intact but is **never rendered** anywhere — it exists only so round-tripping through the app doesn't lose that orphaned data
- **Drag & drop reorder**: each rail item carries a ⠿ handle (native HTML5 drag, no libraries) — dragging over another card shows a top/bottom insertion indicator and dropping calls `moveRegression(platform, id, toIndex)` (index clamped, unknown id no-op); the array order IS the persisted order. Handles are hidden while a search is active and never rendered in readOnly snapshots. jsdom lacks `DragEvent`, so `src/test/setup.ts` carries a minimal test-only polyfill (jsdom#2913)
- **Search with match highlighting**: the rail's search field (`type="search"`, no custom × button, "N/M" counter, query survives tab switches) filters the ACTIVE tab case-insensitively against version, url and the schema's **visible** ticket fields only — a hidden field's stored value can't surface a match (deliberately narrower than the Sprint Tracker's search, which DOES match hidden columns — see "Sprint Tracker" above and "Known issues"). A ticket match surfaces the version in the rail and the detail shows only matching rows (`visibleTicketIds`); with no visible match at all the detail falls to its empty state (`regression.selectVersion`). `forceExpanded` no longer exists — the panel variant is always expanded. Matched substrings render as `<mark>` via `src/utils/highlight.tsx` (`highlightMatches`/`containsMatch`/`MARK_STYLE`) in the version, the Excel link name and cell overlays (focus lifts the overlay for raw editing); when the match lives only in the hidden URL of a "Nombre - URL" cell, the whole visible name is tinted with a `regression.matchInUrl` tooltip instead
- **`safeTab` guard**: the active platform tab is tracked by id, but the schema can hide the very platform the user is looking at (from the columns editor, mid-session); `RegressionTracker` derives `safeTab` from `activeTab` and reroutes to the first visible platform whenever `activeTab` no longer resolves to one, so the board never renders against a platform that has vanished from the tab bar
- Storage: `regressions` + `archived` (+ legacy `board`, when present) in `acgen_regressions`; column widths for legacy `TrackerGrid` snapshots in `acgen_regression_col_widths`

(3) **Cerrado, se conserva por si reaparece.** Durante la ventana de despliegue de la Fase 4 (2026-08-15), una pestaña que siguiera con el bundle **pre-Fase-4** podía podar any ticket field a user added from a tab already on the new schema, and destroy it on that old tab's next write — the retired `normalizeTicket` rebuilt every ticket as a fresh object with exactly the six historical keys, so a seventh field it doesn't know about gets dropped on write. Nothing on this branch (or any later one) can fix it, because the pruning code was already shipped before this feature existed; the only cure is every open tab eventually reloading onto the new bundle. Extra *platform* keys are unaffected by the same old bundle — its hydration always spread the stored `regressions` object over its own defaults, which preserves unknown platform keys instead of pruning them. **Fases 4 y 5 de productización están hechas, mergeadas y en producción** — cada una con su fila propia en "Evolution history" más abajo, donde vive el detalle. La Fase 5 se verificó además con 27/27 asertos en navegador real contra producción (`scripts/browser-checks/`, ver su README).

Comportamientos deliberados del Sprint Tracker en producción, no defectos ni pendientes:

- **Sprint tabs and columns can't be deleted or reordered** — the Sprint Tracker's grid is positional (a column's `dataIndex` IS its on-screen position and every stored width is keyed by that index), so either operation would require migrating the grid to keyed rows plus migrating stored widths from index-keyed to id-keyed. Hiding an entry already covers the practical case: the data survives and the entry can be shown again exactly as it was, same as Regression Tracker fields/platforms.
- **Renaming a Sprint tab or column fixes the text in both languages, same tradeoff as Fase 4's Regression Tracker**: writing a literal `label` wins over the default `labelKey` translation, so a renamed tab/column reads identically in ES and EN — there is no way to give it two different per-language labels once renamed.
- **The schema is global — archived sprints are read through it too, so a historical view is not immutable.** There is exactly one `acgen_schema`, shared by every sprint; renaming or hiding a column changes how an already-archived sprint reads, not just the live one. No data is lost (hiding never deletes: the value stays in the sprint's `tabGrid` at its `dataIndex` and comes back the moment the column is shown again), but the archived sprint you open next month may be labelled differently, or be missing a column, versus what it looked like when it was archived. Freezing a per-sprint copy of the schema at archive time would fix it and is deliberately not done in this branch. **Archived sprints are now genuinely read-only** (2026-08-15, follow-up branch): `SprintDashboard` passes both `dragDisabled` and `readOnly`, so cells aren't editable, "+ Fila" is gone and the schema editor button is hidden — before this, only row drag-and-drop was disabled and you could silently corrupt a closed sprint by typing in a cell. It ships together with **Desarchivar** (`unarchiveSprint`, clears `archived` and `endDate`) because archiving used to be one-way: freezing a sprint with no way back would have left a typo spotted after closing it stuck forever. Known trade-off: `TrackerGrid` makes column widths ephemeral in `readOnly` (same as the Regression Tracker's legacy snapshots), so resizing an archived sprint's columns no longer persists between visits.
- **Across browser tabs everything syncs now (2026-09-02, PR #54).** `useSprints`, `useRegressions` and `useHistory` listen to the native `storage` event and rehydrate (a `lastPersisted` ref stops the write-back bounce), and every hook writes through one `writeStorage()` in `src/services/persistence.ts`, which fires the same-tab sync event and announces quota failures. The old caveat ("a second tab's next edit overwrites the first tab's sprints") is gone.
- **The two trackers' searches deliberately disagree about hidden columns — NOT an inconsistency to fix.** Full reasoning, Jorge's 2026-08-15 decision and the tests that pin it: see "Sprint Tracker" above. Mentioned here only so nobody reaches this list, spots the difference and "fixes" it.
